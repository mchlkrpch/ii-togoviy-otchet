# Проверка отчетности по первичным документам

Локальное рабочее место на Python и React для сверки отчета с PDF, DOCX, XLSX и фотографиями. Карточка показателя показывает формулу, подставленные значения и исходные фрагменты. Ручные исправления сохраняются с причиной и пересчитывают зависимые показатели.

## Техническое ядро

Система преобразует XLSX, DOCX, PDF и фотографии в структурированную модель данных с привязкой к исходным фрагментам.

- **XLSX.** `openpyxl` извлекает листы, значения, формулы и объединения ячеек.
- **DOCX.** Разбор XML-разметки OOXML восстанавливает абзацы, заголовки и таблицы.
- **PDF.** PyMuPDF извлекает текст, его координаты и векторные границы таблиц.
- **Сканы и фотографии.** Pillow подготавливает изображение, OpenCV выделяет линии и восстанавливает сетку таблиц, Tesseract распознает текст. Алгоритмы разбора таблиц определяют объединения ячеек и восстанавливают иерархию многоуровневых заголовков. Неоднозначные результаты помечаются для ручной проверки.

JSON-представление объединяет реквизиты, текстовые блоки, таблицы, пути строк и столбцов, значения, единицы измерения и, где применимо, формулы и их зависимости. Привязка указывает документ и место в нем, например лист и ячейку или страницу и координаты. Для распознанных фрагментов сохраняются метод извлечения и оценка уверенности. По этим метаданным система подбирает источники для формул, а пользователь может открыть исходный фрагмент и проверить связь.

## ИИ для формул

В редакторе формулы кнопка **Предсказать ИИ** подбирает источники для выбранного показателя. Локальная модель `cointegrated/rubert-tiny2` на CPU оценивает смысловую близость названий, разделов, заголовков столбцов, периодов и единиц измерения. Правила учитывают коды строк, иерархию таблиц и совместимость полей. Из подходящих источников система строит до трех вариантов формулы, например сумму дочерних строк, расчет остатка, маржинальности или темпа роста. При необходимости формула приводит единицы к масштабу отчета и округляет результат.

Система подбирает формулу по метаданным и подставляет числовые значения на этапе предпросмотра. Для каждого варианта редактор показывает исходные фрагменты, расчет и расхождение с отчетом. Если данных недостаточно или несколько связей равнозначны, редактор сообщает об этом. Кнопка **Использовать в черновике** переносит формулу и привязки в редактор. Пользователь может изменить черновик и сохранить его после проверки.

Для локального запуска предсказаний после первого запуска приложения установите зависимости и скачайте веса. Команды выполняются из корня проекта на macOS или Linux.

```bash
src/.venv/bin/python -m pip install torch 'transformers==4.57.6'
src/.venv/bin/python src/prepare_model.py
```

После загрузки весов предсказания работают локально без доступа к интернету.

## Единый редактор

В одном интерфейсе открываются XLSX, DOCX, PDF и фотографии. В XLSX можно редактировать ячейки, в DOCX — текст и оформление. Для PDF и фотографий редактор показывает извлеченные поля поверх оригинала и позволяет исправлять значения и разметку. В редакторе формул можно выделить значение в исходном документе, связать его с переменной и проверить расчет до сохранения. Предложения ИИ используют ту же модель данных и сохраняются после подтверждения пользователем.

## Запуск

Нужны Python 3.11+, Node.js 22.12+ с npm и Tesseract с языками `rus` и `eng`. Для первой установки зависимостей нужен интернет. Документы обрабатываются локально.

На macOS один раз установите OCR

```bash
brew install tesseract tesseract-lang
```

Из корня проекта запустите

```bash
python3 src/run.py
```

Скрипт создаст `src/.venv`, установит зависимости, соберет интерфейс и откроет **http://127.0.0.1:8765**. Последующие запуски используют подготовленное окружение. На macOS также можно открыть `src/start.command` двойным щелчком в Finder.

Остановка — `Ctrl+C` в терминале. Дополнительные варианты запуска

```bash
python3 src/run.py --port 8877
python3 src/run.py --no-browser
```

На Ubuntu/Debian OCR устанавливается командой

```bash
sudo apt-get install tesseract-ocr tesseract-ocr-rus tesseract-ocr-eng
```

В Windows установите Python, Node.js и Tesseract с `rus` и `eng` в `PATH`, затем выполните `python src/run.py`.

## Docker Compose

Нужны Docker Engine и Docker Compose. Образ включает Tesseract и языковые пакеты OCR для русского и английского. Команды настройки предсказания формул выше рассчитаны на локальный запуск.

```bash
docker compose -f src/compose.yaml up --build -d
```

Приложение откроется по адресу **http://127.0.0.1:8765**. Папка `вводные` подключается для чтения. Состояние сохраняется в `src/.data/docker`.

```bash
docker compose -f src/compose.yaml down
```

Для другого порта задайте `AUDIT_PORT`, например `AUDIT_PORT=8877 docker compose -f src/compose.yaml up --build -d`. Контейнерный запуск в текущей среде не проверялся, поскольку Docker отсутствует.

## Работа с тестовым набором

1. Нажмите **Открыть набор из «вводные»**. Отчет, договор и период загрузятся автоматически. Импорт показывает прогресс и текущий файл.
2. Слева находится **Explorer**: файлы открываются по ссылкам и сгруппированы в окантованные блоки по проектам. Ссылку на любой файл можно открыть в новой вкладке. Первичные документы каждой проверки изначально скрыты и раскрываются стрелкой. В одной проверке можно загрузить несколько отчетов: они отображаются первыми и используют общий пул первичных документов. Двойной клик по названию переименовывает проверку; Enter сохраняет, Escape отменяет. Панель можно растянуть за правую границу или скрыть кнопкой рядом с плюсом. Если перетащить границу почти к левому краю окна, Explorer полностью сворачивается в тонкую вертикальную линию. Потяните линию вправо или нажмите на нее для восстановления; последняя ширина сохраняется. Между панелью и визуализатором нет отступа.
3. Выбранный файл открывается в единственном просмотрщике. Сохраненные переменные отмечены поверх содержимого. Камера свободно перемещается с запасом по краям во всех форматах. Масштаб, страница, лист и положение запоминаются для каждого файла в текущем сеансе браузера. Клик по результату после **=** возвращает к выбранному отчету с сохраненной камерой.
4. Кнопка карандаша возле формулы открывает редактор. Нажмите `/`: символ не вставится, появится меню файлов. Выберите файл, выделите одно число и нажмите **Использовать как переменную** над выделением. Для Excel можно выбрать числовую ячейку. В формулу в позиции курсора вставится `xN`. Существующие исходные ячейки сохраняют свои зависимости; для нового фрагмента сохраняются файл, значение и координаты или строка Word. Перед сохранением показывается пересчет, требуется причина изменения. Для деления используйте кнопку **÷**. Отмена не сохраняет новые переменные. Формула и привязки сохраняются вместе; недопустимые операции и циклы отклоняются.

PDF и фотографии открываются с инструментами поверх оригинала в прямоугольных рамках. XLSX и DOCX открываются во встроенных редакторах с собственными меню и панелями форматирования. Ctrl/⌘ + прокрутка меняет масштаб, Shift + прокрутка перемещает в стороны. Визуализатор начинается у верхнего края и вплотную к Explorer. Новую проверку можно добавить плюсом в Explorer.

По умолчанию в панели инструментов показан закрытый замок **Просмотр**. Нажмите его для режима **Изменение**. Excel поддерживает редактирование ячеек, Word — текста и оформления. Правки Office сохраняются автоматически с записью в журнал проверки. Для TXT, распознанных числовых полей PDF/фото и полей PDF-форм доступен редактор отдельных значений с причиной изменения. Связанные показатели пересчитываются после сохранения. Отдельную исправленную версию файла можно получить через API `GET /api/cases/{case_id}/documents/{document_id}/edited-file`.

Кнопка **Иерархия полей** находится справа на панели просмотра PDF и изображений. Включите её, чтобы увидеть дерево заголовков и ячеек таблиц, цветные рамки на странице и реквизиты в виде «ключ → значение». Поле можно выбрать на странице или в дереве. Чтобы исправить распознанный текст, переключите **Просмотр** на **Изменение** и сохраните правку в нижней панели. Такие правки сохраняются для документа проекта и не меняют оригинал или расчёты проверки.

5. Меню с многоточием рядом с формулой открывает объяснение статуса, зависимости и ручные исправления.
6. Экспорт HTML для печати, CSV и полного JSON с доказательствами и историей доступен через API `GET /api/cases/{case_id}/export/{html|csv|json}`.

## Сценарий ручной корректировки

Откройте зарплатную ведомость за январь и ячейку `C6`. Исправьте значение с `1010000` на `1010001` и укажите причину. Пересчитаются `C8 = SUM(C6:C7)`, общая зарплата, сверка базы январских взносов и итог. В журнале сохранятся прежнее значение, новое значение, причина и ревизия. Оригинальный файл доступен для сверки.

Вычисляемые итоги источников корректируются через исходные ячейки. Извлеченное значение отчета можно уточнить кнопкой **Исправить OCR**. Ручная формула возвращается к автоматической кнопкой **Вернуть автоматическую формулу**.

Для своего комплекта нажмите **Загрузить документы**, отдельно выберите отчет и первичные файлы. Укажите договор и период, если в комплекте отсутствует `00_README`. Затем уточните статьи и связи показателей с источниками.

## Статусы и правила

При незаданном договоре или периоде проверка отмечается как предварительная. Для уточнения области расчета откройте **Параметры проверки**. Числовые совпадения показываются отдельно от подтверждения источников.

Статусы обозначены поверх ячеек оригинала отчета. Формула и сравнение сумм находятся в баре поверх оригинала; кнопка с многоточием открывает подробности и исправления. Связанные оригиналы открываются через файловую панель и кликабельные переменные формулы.

- **Подтверждено** — есть расчет по источникам, сумма укладывается в допуск и зависимости подтверждены.
- **Вопрос** — сумма по проверяемым источникам или надежно прочитанная арифметика расходится с отчетом.
- **Требует проверки** — есть сомнение в распознавании или зависимости. Числовое совпадение с первичкой показывается отдельно.
- **Нет подтверждения** — нет независимых источников или полного периода. Внутреннее арифметическое совпадение сохраняется отдельной проверкой.
- **Исключено** — повтор, другой договор, другой период, копия отчета или ручное решение.

Деньги считаются через `Decimal`, округление до копеек — `ROUND_HALF_UP`. Допуск по умолчанию включительно `0,01 ₽`, его можно изменить. Единица трудоемкости хранится отдельно от рублей. Месячные ведомости проверяются на полноту периода. Тариф страховых взносов автоматически не предполагается.

Поддерживаются ссылки XLSX на ячейки и прямоугольные диапазоны, ссылки на другие листы, `SUM`, `MIN`, `MAX`, `AVERAGE`, `ROUND`, проценты и арифметические операции. Формулы рассчитываются из исходных ячеек, включая файлы без сохраненного Excel-кэша. Пустые ссылки, неподдерживаемые формулы и циклы отмечаются явно.

Сопоставление статей основано на правилах по реквизитам и содержанию. Интерфейс показывает найденный признак и позволяет изменить статью. OCR сохраняет координаты, оценки и варианты чтения спорных чисел.

Автоматическая разметка широкого скана реализована для 17-графной формы КФЗ из набора. В других XLSX извлекаются числовые ячейки и формулы. В остальных PDF/DOCX извлекаются денежные показатели с фрагментами, связи задаются вручную. Нестандартная форма, поврежденный файл и сомнительный OCR требуют уточнения оператором.

## Архитектура и хранение

```text
Файлы → текст / OCR / ячейки → реквизиты и координаты
      → фильтрация договора, периода и дублей → сопоставление статей
      → граф формул с Decimal → статусы и распространение сомнений
      → React UI → исправление с причиной → новый расчет и ревизия
```

| Компонент | Назначение |
| --- | --- |
| `backend/extraction.py` | Форматы документов, OCR, сетка КФЗ, факты и координаты |
| `backend/excel.py` | Чтение и безопасный пересчет XLSX |
| `backend/money.py` | Десятичная арифметика и разрешенный язык формул |
| `backend/engine.py` | Источники, проверки, граф, сомнения и корректировки |
| `backend/ingest.py` | Импорт, область проверки и прогресс |
| `backend/store.py` | SQLite, транзакции, ревизии и задания |
| `backend/app.py` | API, оригиналы, фрагменты и экспорт |
| `frontend/src` | React UI для показателей, документов, формул и журнала |
| `run.py` | Подготовка окружения и запуск локального сервера |
| `evaluate.py` | Отдельная оценка по эталону |

SQLite и копии документов сохраняются в `src/.data`. Извлеченные данные отделены от ручных исправлений. Номер ревизии защищает от перезаписи свежих изменений параллельной вкладкой. Завершенные проверки доступны после перезапуска. Прерванный импорт отмечается как неуспешный, комплект можно загрузить повторно.

Переменные `AUDIT_DATA_DIR` и `AUDIT_INPUT_DIR` задают папки состояния и демонстрационного набора. Внешние сервисы для обработки документов не используются. Локальный сервер слушает `127.0.0.1`. Схема API доступна по `/docs`.

## CLI для иерархии PDF

`parse_structure.py` используется режимом «Иерархия полей» и доступен как отдельная команда: восстанавливает линейную сетку таблиц, объединенные ячейки, дерево многоуровневых заголовков и пути к значениям. Названия и количество граф читаются из документа. Для текста используется текстовый слой PDF, для сканов — локальный Tesseract. Нужны Python 3.12+ для зафиксированных зависимостей и Tesseract с `rus` и `eng`.

```bash
src/.venv/bin/python -m pip install -r src/requirements-structure.txt
src/.venv/bin/python src/parse_structure.py \
  "вводные/01_Карточка_учета_фактических_затрат_этап_3.pdf" \
  -o output/pdf/cost-card.structure.json \
  --tree output/pdf/cost-card.structure.txt \
  --debug-dir output/pdf/debug \
  --cache-dir tmp/pdfs/ocr-cache
```

JSON содержит страницы и текст вокруг таблиц, а в каждой таблице — `header_tree`, `columns`, `rows`, `cells` с координатами в PDF points и размерами объединений. `rows[].values[]` хранит полный `column_path`, точное десятичное значение строкой, исходное OCR-чтение и признак `needs_review`. У спорных числовых ячеек сохраняются альтернативы `ocr_candidates`. Служебные номера граф не становятся строкой данных. Суммы, резерв и строка «Всего» не переименовываются по смыслу: иерархия следует напечатанным заголовкам.

Пример обращения из Python, когда `src` доступен через `PYTHONPATH`:

```python
import json
from decimal import Decimal
from parse_structure import select_field

with open("output/pdf/cost-card.structure.json", encoding="utf-8") as stream:
    document = json.load(stream)
field = select_field(document, ["3 этап, 2026 г.:"], ["Итого"])
amount = Decimal(field["value"])  # 11580377.40
```

Селектор сравнивает полные пути с нормализацией Unicode и пробелов. Пропущенные и неоднозначные поля вызывают `LookupError`. Имя файла и координаты не входят в переносимый селектор. Для двух одинаковых таблиц нужно добавить область поиска; необязательный `table_id` различает таблицы внутри конкретного результата и не является постоянным межфайловым идентификатором.

Проверки:

```bash
PYTHONPATH=src src/.venv/bin/python -m unittest discover -s src/tests -p test_structure_parser.py -v
```

На приложенном скане проверяются 17 граф, 4 уровня шапки, 4 строки данных, 109 физических ячеек и все 60 числовых значений по вручную переписанному эталону. Синтетические проверки покрывают объединения, сдвиг и масштаб сетки, повторяющиеся заголовки и неоднозначные ссылки. Это проверка одного реального шаблона, не оценка качества на произвольном корпусе PDF.

Ограничения: нужны видимые границы таблиц и прямое положение страницы. Таблицы без линий, сильно повернутые сканы и продолжения одной таблицы на разных страницах требуют дополнительных правил; страницы сейчас независимы. При отсутствии сетки сохраняется текст с предупреждением. При отсутствии нумерации граф начало данных определяется эвристикой и помечается предупреждением. Текст вне таблиц сохраняется строками с координатами, без автоматического назначения бизнес полей. OCR может ошибаться даже при высокой оценке уверенности, поэтому `needs_review=false` не заменяет проверку. Для точных межфайловых ссылок названия из OCR следует подтвердить и закрепить в профиле шаблона. Метки в поставляемом JSON остаются исходными результатами OCR, без ручных исправлений.

В результат записываются версии движков, DPI, язык, SHA-256 входного файла и языковых моделей OCR. При одинаковом входе и окружении порядок и сериализация стабильны. Кэш привязан к изображению, настройкам и моделям; внешние сервисы не используются.

## Ключи, значения и обе оси таблицы

Схема `pdf-structure/2` дополняет геометрию модулем `structure_semantics.py`. `key_value_fields` хранит реквизиты с отдельными областями ключа и значения. Пары выделяются по двоеточию или явно увеличенному горизонтальному промежутку между словами. В `key_values` находятся однозначные ключи, например `{"исполнитель": "МФТИ, Физтех"}`. Повторяющиеся ключи перечислены в `ambiguous_keys`; исходные кандидаты сохраняются полностью.

`facts` содержит табличные значения с показателем, единицей, полным путем столбца, иерархией строки и контекстом. Для `34,14` это `metric="Трудоемкость"`, `unit="человеко-месяц"`, `row_context={stage: 3, year: 2026, aggregation: "detail", reference: false}`. Этап, год, месяц и признак итоговой/справочной строки выделяются явными регулярными правилами; единица читается из заголовка. В каждой таблице `row_tree` группирует строки по этапу и периоду; у каждой строки есть `key_values` с ключами в виде полного пути заголовка (JSON Pointer с экранированием `/` и `~`). Одинаковые названия конечных заголовков сохраняют разных родителей.

```python
from structure_semantics import get_key_value, get_fact, find_facts

executor = get_key_value(document, "Исполнитель")["value"]
labor = get_fact(document, metric="Трудоемкость", stage=3, year=2026)
assert labor["value"] == "34.14"
same = get_fact(document, query="трудоемкость за 3 этап 2026")
candidates = find_facts(document, metric="Трудоемкость", stage=3)
```

Структурные фильтры сравниваются точно после нормализации Unicode, регистра и пунктуации. Текстовый запрос разбирает этап/год и требует совпадения всех оставшихся слов (для слов от четырех символов допускается совпадение начала слова). Поиск возвращает всех кандидатов; `get_fact` отклоняет отсутствие и неоднозначность. Это ограниченная детерминированная грамматика, без LLM, эмбеддингов и скрытого выбора ближайшего поля. OCR-опечатки остаются в исходных подписях.

В просмотрщике реквизиты представлены отдельной веткой «ключ → значение». При выборе числа синим подсвечиваются заголовки столбца, оранжевым — подпись и полоса строки. Панель показывает оба пути, единицу и описание факта. Вид «По строкам» группирует значения по горизонтальной иерархии «этап → год». Эти дополнения заменяют прежнее ограничение на отсутствие структурированных реквизитов вне таблиц; исходные текстовые блоки также сохраняются.

## Редактор распознанных полей

Текст исправлений хранится в данных и показывается в таблице под визуализатором: его можно выделить, скопировать и изменить. Поверх PDF распознанный/исправленный текст не рисуется, изображение исходной страницы не закрашивается. Панель редактирования встроена снизу, без модального окна; чтение и копирование доступны даже вне режима изменения.

При перемещении и растягивании рамки включена мягкая привязка к близким краям других полей: порог — 5 экранных пикселей с учетом масштаба. При совпадении появляется направляющая. Alt временно отключает привязку; флажок «Магнит» выключает ее полностью.

Для редактирования вместо обычного статического HTTP-сервера запускается сервер с сохранением:

```bash
src/.venv/bin/python src/structure_server.py --port 8878 --directory output/pdf
```

Откройте `http://127.0.0.1:8878/document-sets.html`, выберите документ и нажмите «Редактировать» внутри просмотрщика. «Текст и границы» позволяет изменить распознанный текст и координаты PDF-прямоугольника. В режиме изменения поле также можно перемещать мышью и растягивать за восемь маркеров; изменение сохраняется после отпускания мыши. Координаты пересчитываются из экранных пикселей в PDF points при любом масштабе.

«Выбрать 2 поля» включает набор пары конечных полей щелчками по странице или дереву. Затем «Объединить» сохраняет один охватывающий прямоугольник и общий текст, удаляя второй узел из дерева. Разрешены разные родители; новое поле помещается к общему предку. Первый идентификатор сохраняется, второй перенаправляется на объединенное поле для прежних глубоких ссылок.

Для разделения выберите конечное поле, нажмите «Разделить», поставьте курсор между двумя частями в исходной строке и нажмите «Разделить по курсору». Части можно исправить в двух текстовых полях. «Подобрать границы» показывает два прямоугольника без сохранения. Python сопоставляет обе части с исходными словами страницы и объединяет их настоящие прямоугольники. При разрезе внутри слова используются приблизительные позиции символов; если текст не сопоставляется, предлагается геометрическое деление с явным предупреждением. После сохранения две части становятся соседними узлами дерева; при необходимости их границы можно уточнить вручную. Правила находятся в `structure_edits.py`, без LLM.

Генератор просмотрщика сохраняет рядом `*.viewer.model.json`: исходное дерево, координаты слов и SHA-256 PDF. Для сканов координаты слов получает локальный Tesseract. Операции пользователя и журнал версий находятся в `output/pdf/edits/<sha256>.json`; оригинальный PDF и исходный результат парсера не перезаписываются. Правки общие для одинакового PDF во всех наборах и восстанавливаются после перезагрузки страницы и перезапуска сервера. Проверка версии запрещает молчаливую перезапись из другого окна.

«Отменить последнее» отменяет последнюю операцию текущего документа с сохранением журнала. «Скачать структуру JSON» выгружает исправленную модель дерева с координатами, версиями и журналом; это модель просмотрщика, отдельная от неизмененного первичного JSON парсера. История помечает наборы с правками для повторной сверки. Формулы в ней показывают исходный пакетный прогон и автоматически по ручному слою не пересчитываются.

```bash
PYTHONPATH=src src/.venv/bin/python -m unittest discover -s src/tests -p test_structure_edits.py -v
PYTHONPATH=src src/.venv/bin/python -m unittest discover -s src/tests -p test_structure_server.py -v
node --test src/frontend/tests/structure_editor.test.mjs
```

Проверяются подбор рамок по словам, разделение внутри слова и приблизительный fallback, объединение и связи дерева, редактирование заголовков и границ, сохранение на диск, отмена, конфликт версий, восстановление после реального перезапуска HTTP-сервера, экспорт и действия интерфейса. На поле «организация» PDF-с. 10 аудиторского отчета две части сопоставлены со словами с покрытием 100%.

## Табличный редактор XLSX

XLSX открывается во встроенном редакторе Univer 1.5.0: меню «Файл», «Правка», «Вид», «Вставка», «Формат», «Данные», «Инструменты», панель форматирования, строка формул, адрес ячейки, листы и контекстные меню. Книга работает локально, без Google-аккаунта, облачного обмена и AI-функций.

Снимите замок **Просмотр**, чтобы редактировать. Изменения автоматически сохраняются в проекте и журнале проверки; `Ctrl/⌘+S` сохраняет немедленно. При ошибке сохранения черновик остается в браузере; его можно восстановить через «Файл». В режиме редактирования доступны:

- значения, формулы, копирование/вырезание/вставка, отмена/повтор и поиск/замена;
- шрифты, размер, жирный/курсив/подчеркивание/зачеркивание, цвета текста и заливки, границы, выравнивание, перенос, поворот, числовые форматы;
- вставка/удаление строк и столбцов, их размеры, объединение ячеек, листы, закрепления и сетка;
- сортировка, фильтры, условное форматирование, проверка данных, выпадающие списки, примечания, ссылки и таблицы;
- выгрузка XLSX, CSV текущего листа и полного JSON-снимка; печать выбранного диапазона.

Плавный масштаб: `Ctrl/⌘+прокрутка`, ползунок или точное дробное значение в процентах. Точка под курсором остается на месте. Состояние камеры запоминается при переходах между файлами. Кнопки `Ctrl/⌘ + +/-/0` также работают.

Проверки используют устойчивые идентификаторы исходных ячеек. Вставка строк и перенос ячеек обновляют местоположение источника; удаленное или очищенное исходное число не заменяется соседним значением. Новые пустые ячейки, вставленные в SUM, учитываются как нули; отсутствие первичного документа по-прежнему не считается нулем. Формулы табличного движка, которые сервер проверки не умеет независимо вычислять, сохраняются, но остаются непроверенными в графе сверки.

Это не полная копия Google Sheets. Диаграммы, сводные таблицы, Apps Script, макросы, облачные интеграции и полный диалог печати Google пока не реализованы. Точный снимок форматирования и ресурсов плагинов сохраняется внутри проекта и JSON. Экспорт XLSX переносит значения, формулы, обычные стили, размеры, объединения, листы, закрепления и примечания; полноценный обмен условным форматированием, валидацией, ссылками и другими ресурсами плагинов с внешними редакторами еще требует отдельного конвертера. Произвольные исходные диаграммы и другие расширенные OOXML-объекты пока не представлены в новом редакторе. Исходный файл хранится отдельно и не перезаписывается.

### Проверка табличного интерфейса в Chrome

Сценарий `src/frontend/browser-tests/spreadsheet.mjs` проверяет реальные операции меню, масштаб, сохранение, экспорт и возвращение в книгу. Он требует отдельный сервер с одноразовой копией данных и намеренно отказывается работать на рабочем порту 8765:

## Редактор документов DOCX

Выберите DOCX в Explorer. Встроенный редактор на Tiptap открывает документ в той же рабочей области, где работают таблицы. Интерфейс включает имя файла, меню «Файл», «Правка», «Вид», «Вставка», «Формат», «Инструменты», панель форматирования, структуру заголовков, линейку и белую страницу. Меню «Таблица» появляется при выборе ячейки.

Снимите замок **Просмотр** для редактирования. Доступны следующие операции.

- Шрифты и размер, жирный и курсив, подчеркивание и зачеркивание, цвет текста и выделения, верхний и нижний индексы.
- Заголовки, выравнивание, списки и задачи, отступы, межстрочный и межабзацные интервалы.
- Таблицы, строки и столбцы, объединение ячеек, заливка и границы.
- Изображения с устройства и из буфера обмена, ссылки, специальные символы, дата, горизонтальная линия и разрыв страницы.
- Поиск и замена, отмена и повтор, форматированный буфер обмена, подсчет слов и знаков, проверка орфографии браузером.
- Размер и ориентация страницы, поля, колонтитулы и номера страниц.
- Сохранение в проекте, экспорт DOCX, PDF, HTML и TXT, печать.

Правки автоматически сохраняются с задержкой 850 мс. `Ctrl/⌘+S` сохраняет сразу. Локальный черновик доступен в меню «Файл», если сохранение прервалось. Перед экспортом редактор дожидается текущего сохранения. Буфер обмена зависит от разрешений браузера, ошибка отображается в редакторе.

Сохраненные переменные подсвечиваются прямо в тексте. Число выделяется ярким зеленым, окружающий контекст — светлым. Редактор формулы позволяет выделить число в DOCX и использовать его как переменную. У абзацев и строк таблиц сохраняются устойчивые идентификаторы. Правка суммы пересчитывает зависимые показатели. Удаленный источник получает сомнение в графе проверки.

Масштаб меняется плавно через `Ctrl/⌘+прокрутку`, ползунок или поле процентов. Масштабируется вся страница с фиксированной логической шириной, сохраняя переносы строк. Камера и масштаб запоминаются при переходах между DOCX и XLSX.

Браузер показывает непрерывную бумагу с явными разрывами страниц. Автоматическая пагинация выполняется при экспорте. PDF использует собственную потоковую верстку, поэтому его расположение объектов может отличаться от Word. Многосекционная разметка упрощается до общих параметров страницы. Сложные объекты исходного Word сохраняются в DOCX, их браузерное представление и редактирование ограничены. Редактирование сносок, уравнений, предложенных исправлений, комментариев и совместная работа пока отсутствуют. У изображений доступны импортированные размеры и выравнивание, интерактивные маркеры изменения размера пока отсутствуют.

API возвращает модель редактора через `GET /api/cases/{case_id}/documents/{document_id}/rich-document`. Изменения передаются существующему `/changes` с видом `rich_document`. Экспорт PDF и HTML доступен через `/rich-document/export/{pdf|html}`, DOCX — через `/edited-file`.

Браузерный сценарий использует отдельный сервер с одним одноразовым тестовым комплектом.

```bash
cd src/frontend
AUDIT_BROWSER_TEST_URL=http://127.0.0.1:8766 node browser-tests/documents.mjs
```

Он проверяет геометрию текста при разных масштабах, форматирование, правку исходной суммы и пересчет, таблицы, параметры страницы, экспорт и сохранение камеры при переходах между редакторами.
